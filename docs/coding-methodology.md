# Research-Grade Coding Methodology

## Phase 10 Enhancement: AI-Assisted Sentiment, Aggression & Cyberbullying Coding

**IMPORTANT:** This document explains the coding system in clear language for research transparency and supervisor review.

---

## 1. OVERVIEW

This system helps researchers systematically code participant responses to experimental video stimuli across three **separate and distinct** coding dimensions:

1. **Sentiment** - Emotional/evaluative orientation
2. **Aggression** - Hostile or threatening language/behavior
3. **Cyberbullying** - Specific harmful online behavior against persons

### Critical Research Principle:

**The AI provides CODING SUGGESTIONS. Human researchers make FINAL DECISIONS.**

- AI output is a **suggestion**, not a final classification
- Human review is **required** for all coding
- The system does NOT claim 100% accuracy
- Negative sentiment ≠ Aggression ≠ Cyberbullying

---

## 2. WHY THREE SEPARATE DIMENSIONS?

### Common Misconception:
"Negative comment = Cyberbullying"

### Reality:
These are DISTINCT concepts that must be coded separately:

**Example 1: Negative but NOT cyberbullying**
> "I strongly disagree with this video. The argument is flawed."

- **Sentiment:** Negative ✓
- **Aggression:** None (critique of idea, not person)
- **Cyberbullying:** No (no personal targeting)

**Example 2: Negative AND potentially cyberbullying**
> "You are an idiot. People like you should be ashamed."

- **Sentiment:** Negative ✓
- **Aggression:** High (insulting language + personal attack)
- **Cyberbullying:** Possibly (personal targeting + humiliation - requires review)

**Why separate?**
- Research integrity requires precise classification
- Statistical analysis requires distinct variables
- Ethical research demands we don't over-classify negative speech as cyberbullying

---

## 3. SENTIMENT ANALYSIS

### What is Sentiment?

Sentiment answers: "What is the emotional/evaluative orientation of this response?"

### Categories:
- **POSITIVE** - Favorable, supportive, agreeable
- **NEUTRAL** - Factual, balanced, no strong evaluation
- **NEGATIVE** - Unfavorable, critical, disagreeing
- **MIXED** - Contains both positive and negative elements

### Important Notes:
1. Sentiment measures emotional tone, NOT behavior
2. Negative sentiment does NOT automatically mean aggression
3. Context matters more than individual words

### Examples:

**Positive:**
> "I really enjoyed watching this. It made me think about social media differently."

**Neutral:**
> "The video presented information about online communication. I watched it carefully."

**Negative:**
> "I disagree with the message in this video. The arguments were not convincing."

**Mixed:**
> "The topic was interesting, but the way it was presented was confusing and frustrating."

---

## 4. AGGRESSION CODING

### What is Aggression?

Aggression answers: "How much hostile, threatening, or attacking language/behavior is present?"

### Key Distinction:
**Critique of IDEAS ≠ Aggression toward PERSONS**

### Categories:
- **NONE** - No hostile or aggressive language
- **MILD** - Minor hostile language, not directed at persons
- **MODERATE** - Clear hostile language or personal insults
- **SEVERE** - Threatening, intensely hostile, or attacking behavior

### Levels (0-10 scale):
- 0-2: None/minimal
- 3-4: Mild
- 5-7: Moderate
- 8-10: Severe

### Critical Coding Rules:

**NOT Aggressive (Critique):**
> "This idea is stupid. The logic doesn't make sense."
- **Aggression:** None/Mild
- **Why:** Critiquing the idea/video, not attacking a person

**IS Aggressive (Personal Attack):**
> "You are stupid. Only an idiot would think this way."
- **Aggression:** Moderate/Severe
- **Why:** Personal targeting + insulting language

### Examples with Explanations:

| Response | Aggression | Why |
|----------|------------|-----|
| "I disagree completely." | None | Disagreement without hostility |
| "This makes no sense." | None | Critique of content |
| "What a dumb video." | Mild | Insulting language toward content |
| "The person in this is an idiot." | Moderate | Personal insult |
| "You should be hurt for saying this." | Severe | Threatening language |

## 5. CYBERBULLYING CODING

### What is Cyberbullying?

Cyberbullying is **specific harmful behavior** that meets multiple criteria. It is NOT just:
- Negative sentiment
- Disagreement
- Criticism of ideas
- Use of harsh words

### Approved Cyberbullying Criteria:

**MUST include:**
1. **Personal Targeting** - Directed at a person, not an idea
2. **Harmful Intent/Effect** - Insulting, humiliating, threatening, or harassing

**Additional considerations (if applicable):**
3. Repetition (where observable)
4. Power imbalance (where determinable)
5. Public/social context

### Types of Cyberbullying:
- **NONE** - Does not meet cyberbullying criteria
- **HARASSMENT** - Repeated offensive messages or threats
- **DENIGRATION** - Spreading harmful information, humiliation
- **FLAMING** - Intense argument with hostile/vulgar language
- **IMPERSONATION** - Pretending to be someone else
- **OUTING** - Sharing private information
- **EXCLUSION** - Deliberately excluding someone
- **CYBERSTALKING** - Repeated threatening/intimidating behavior
- **OTHER** - Fits cyberbullying definition but not above categories

### Severity (if present): 0-10 scale
- 0-3: Low (meets minimal criteria)
- 4-7: Moderate (clear harmful intent/effect)
- 8-10: Severe (intense, threatening, highly harmful)

### Coding Decision Tree:

```
Is there PERSONAL TARGETING?
  ↓ No → NOT cyberbullying
  ↓ Yes
    ↓
Is there HARMFUL BEHAVIOR (insult, threat, humiliation)?
  ↓ No → NOT cyberbullying (may still be negative/aggressive)
  ↓ Yes
    ↓
Does it meet approved cyberbullying criteria?
  ↓ Yes → Code as CYBERBULLYING with type + severity
  ↓ Uncertain → Mark for EXPERT REVIEW
```

### Examples with Explanations:

**NOT Cyberbullying:**
> "This video is horrible. The message is completely wrong."
- **Personal Targeting:** No (critiques video/message)
- **Cyberbullying:** No
- **Why:** Negative sentiment toward content, not person

**NOT Cyberbullying (Harsh but Idea-Focused):**
> "This is the dumbest argument I've ever heard."
- **Personal Targeting:** No (critiques argument)
- **Cyberbullying:** No
- **Why:** Strong disagreement, but directed at ideas

**POSSIBLY Cyberbullying (Needs Review):**
> "The person saying this is really stupid."
- **Personal Targeting:** Yes (insults person)
- **Harmful Behavior:** Yes (insult)
- **Cyberbullying:** Uncertain (single insult - review needed)
- **Why:** Meets some criteria but may not reach severity threshold

**LIKELY Cyberbullying:**
> "You are a worthless loser. Everyone should see how pathetic you are."
- **Personal Targeting:** Yes (direct attack)
- **Harmful Behavior:** Yes (insult + humiliation + intent to spread)
- **Cyberbullying:** Yes - Type: Denigration, Severity: 7-8
- **Why:** Personal attack + public humiliation + harmful intent

## 6. HOW THE AI CODING WORKS

### AI Role: SUGGESTION ONLY

The AI coding system:
1. **Reads** the participant's response (original text NEVER modified)
2. **Analyzes** context, not just keywords
3. **Evaluates** each dimension separately
4. **Provides** evidence for its suggestions
5. **Indicates** confidence level
6. **Flags** responses needing human review

### What AI CANNOT Do:
- ❌ Make final research decisions
- ❌ Guarantee 100% accuracy
- ❌ Replace human judgment
- ❌ Understand all cultural context
- ❌ Detect sarcasm reliably
- ❌ Read participant intent

### What AI CAN Do:
- ✅ Process many responses quickly
- ✅ Provide consistent initial coding
- ✅ Identify clear patterns
- ✅ Flag ambiguous cases
- ✅ Provide evidence for suggestions
- ✅ Free researcher time for complex cases

---

## 7. CODING WORKFLOW

### Step-by-Step Process:

**Step 1: AI Analysis (Automatic)**
```
Participant submits response
     ↓
System analyzes response
     ↓
AI generates coding suggestion:
  - Sentiment with evidence
  - Aggression with evidence
  - Cyberbullying with evidence
  - Confidence scores
     ↓
Suggestion stored (NOT final coding)
```

**Step 2: Human Review (Required)**
```
Researcher views:
  - Original response
  - AI suggestion
  - Evidence/rationale
  - Confidence scores
     ↓
Researcher decides:
  - ACCEPT: AI suggestion is correct
  - MODIFY: Adjust coding categories
  - REJECT: Code manually
  - UNCERTAIN: Mark for expert review
     ↓
Researcher's decision = FINAL CODING
```

**Step 3: Final Storage**
```
Both stored separately:
  - AI suggestion (audit trail)
  - Human final coding (research data)
     ↓
Original response PRESERVED
     ↓
Full audit trail maintained
```

### Why This Approach?

1. **Research Integrity:** Human expertise guides final decisions
2. **Transparency:** AI and human coding both visible
3. **Auditability:** Complete record of coding process
4. **Efficiency:** AI handles simple cases, human handles complex
5. **Quality:** Uncertain cases get expert review

## 8. CONFIDENCE & UNCERTAINTY

### Confidence Levels:

**High Confidence (0.7-1.0):**
- Clear, unambiguous response
- Strong evidence for classification
- Context fully supports coding

**Medium Confidence (0.4-0.7):**
- Some ambiguity present
- Mixed signals
- May need human judgment

**Low Confidence (0.0-0.4):**
- Highly ambiguous
- Insufficient evidence
- **REQUIRES** human review

### When to Mark "Uncertain":

Mark responses as UNCERTAIN when:
- Response is ambiguous or contains sarcasm
- Cultural context unclear
- Mixed evidence across criteria
- Borderline between categories
- You're not confident in classification
- Expert review would be valuable

**IMPORTANT:** It's better to mark uncertain than to guess!

---

## 9. ORIGINAL RESPONSE PRESERVATION

### Critical Rule: NEVER MODIFY ORIGINAL RESPONSE

The participant's exact response is the primary research record.

**What is ALWAYS preserved:**
- Exact text submitted by participant
- Original spelling, grammar, punctuation
- Original language (English, Urdu, mixed, etc.)
- Exact timestamp
- All metadata

**What is NEVER done:**
- ❌ Correcting spelling/grammar
- ❌ Translating to English
- ❌ Removing "offensive" words
- ❌ Cleaning or sanitizing text
- ❌ Replacing with AI-generated text
- ❌ Modifying for "better" coding

**Why?**
- Research ethics require authentic data
- Modifications bias analysis
- Original context must be preserved
- Audit trail requires original text

## 10. CODING FRAMEWORK VERSION CONTROL

### Why Versioning Matters:

During a research study, coding criteria MUST remain consistent.

**Versioning tracks:**
- Coding categories used
- Criteria definitions
- Methodology changes
- AI model versions
- Framework updates

**Rules:**
1. **During active study:** Do NOT change coding framework
2. **If changes needed:** Create NEW version
3. **Each coding stores:** Framework version number
4. **Analysis must account for:** Version differences

### Example:
```
Version 1.0: Original cyberbullying criteria (Responses 1-100)
Version 1.1: Added "threatening" subcategory (Responses 101-200)

Analysis: Must note that versions differ or recode 1-100
```

## 11. DESCRIPTIVE VS INFERENTIAL ANALYSIS

### What This System Provides: DESCRIPTIVE STATISTICS

The system calculates:
- Total responses coded
- Number/percentage with cyberbullying
- Mean aggression scores
- Sentiment distributions
- Comparison counts between conditions

### What This System DOES NOT Provide:

- ❌ Statistical significance testing
- ❌ P-values
- ❌ Causal conclusions
- ❌ "Proof" of effects

### Example of Correct Reporting:

**System Output:**
```
Anonymous condition: 60/300 responses coded as cyberbullying (20%)
Identifiable condition: 30/300 responses coded as cyberbullying (10%)
```

**Correct Interpretation:**
"Descriptive analysis shows cyberbullying was coded in 20% of anonymous condition responses versus 10% of identifiable condition responses. Inferential statistical analysis (to be conducted separately) will determine whether this difference is statistically significant."

**INCORRECT Interpretation:**
"Anonymity causes cyberbullying." ❌
"Anonymity significantly increases cyberbullying." ❌

## 12. LANGUAGE HANDLING

### Multilingual Support:

Participants may respond in:
- English
- Urdu (Arabic script)
- Roman Urdu (Romanized Urdu)
- Mixed English/Urdu
- Informal/slang language

### System Approach:

1. **Language Detection:** AI attempts to detect language
2. **Confidence Score:** Indicates detection certainty
3. **Analysis:** Works with detected language where possible
4. **Uncertainty:** Low-confidence language = requires human review

### Important Notes:

- **Translation NOT automatic:** Original language preserved
- **Cultural context:** May require human cultural knowledge
- **Romanization:** Roman Urdu challenging for automated systems
- **Mixed language:** Requires careful interpretation

## 13. MODEL VALIDATION & ACCURACY

### Current Status: BASELINE SYSTEM

The current AI coding uses a **rule-based baseline system**.

**What this means:**
- Context-aware pattern matching
- Explicit criteria checking
- Transparent, explainable logic
- NOT a trained machine learning model
- NOT validated for accuracy

### Before Research Publication:

**Validation Required:**
1. Create reference coding set (manually coded by experts)
2. Compare AI suggestions to expert coding
3. Calculate agreement metrics (accuracy, precision, recall, Cohen's kappa)
4. Document validation results
5. Report accuracy limitations

### No Accuracy Claims:

We **DO NOT** claim:
- ❌ "100% accurate"
- ❌ "Scientifically validated"
- ❌ "Proven effective"
- ❌ "Automatically determines cyberbullying"

We **DO** state:
- ✅ "AI provides coding suggestions"
- ✅ "Human review is required"
- ✅ "Validation in progress"
- ✅ "Accuracy to be determined"

## 15. AUDIT TRAIL & TRANSPARENCY

### What is Logged:

For every coding:
- Original participant response
- AI suggestion (all dimensions)
- AI confidence scores
- AI evidence/rationale
- Model name and version
- Framework version used
- Human final coding
- Human reviewer identity
- Review action (accept/modify/reject)
- Timestamps (AI analysis, human review)

### Why This Matters:

- **Research integrity:** Full transparency
- **Supervisor review:** Can verify methodology
- **Publication:** Can explain exact process
- **Replication:** Others can understand approach
- **Quality control:** Can identify coding issues

## 16. HOW TO EXPLAIN TO SUPERVISOR

### Simple Explanation:

"Our response coding system uses AI to provide **initial coding suggestions** for sentiment, aggression, and cyberbullying. These are three separate dimensions - negative sentiment doesn't automatically mean aggression or cyberbullying.

The AI analyzes each response and suggests coding categories along with evidence and confidence scores. A human researcher then reviews each suggestion and makes the final decision: accept, modify, reject, or mark as uncertain.

The system preserves the original participant response unchanged and maintains a complete audit trail of both AI suggestions and human final coding.

We make no claims of 100% AI accuracy. Human review is required, and final research conclusions are based on human-approved coding, not automated classification."

### Key Points for Supervisor:

1. **Not a black box:** Logic is transparent and explainable
2. **Human-centered:** Researcher makes final decisions
3. **Evidence-based:** AI provides rationale for suggestions
4. **Conservative:** Flags uncertain cases for review
5. **Auditable:** Complete record of coding process
6. **Ethical:** Original responses never modified
7. **Scientifically sound:** Separates sentiment, aggression, cyberbullying
8. **Honest:** No unsupported accuracy claims

## 19. TROUBLESHOOTING

### Common Issues:

**Issue:** AI suggests cyberbullying but response seems like disagreement
**Solution:** Review evidence. If personal targeting absent, modify coding.

**Issue:** Low confidence scores on many responses
**Solution:** This is normal for ambiguous cases. Human review working as intended.

**Issue:** AI and human coding frequently disagree
**Solution:** Document patterns. May indicate need for framework refinement or AI improvement.

**Issue:** Unsure if response is cyberbullying
**Solution:** Mark as UNCERTAIN. Better to flag for expert review than guess.
